# 05. System Workflows & Patterns

Specific operational routines engineered to recover from task paralysis, handle distraction streams, and allow instant context restoration.

---

## Pattern 1: Stateless Task Resumability (Checkpointing)
* **Problem:** When interrupted, working memory state (*variables, active file, next step*) is wiped. Rebuilding context takes 15–30 minutes of high cognitive energy.
* **Solution:** Treat focus tasks like **stateless microservices**. Never switch context without leaving a **Visual Breadcrumb**.
* **Execution:** Before turning away from a task, record a single sentence:
  > *"When I return, click [X] and type [Y]."*

---

## Pattern 2: Circuit Breakers for Task Paralysis
* **Problem:** Complex projects overwhelm limited working memory slots, triggering executive dysfunction and complete task freeze.
* **Solution:** In software engineering, a circuit breaker isolates failures to prevent system-wide crashes.
* **Execution:** If frozen for > 3 minutes, **trip the circuit breaker**. Drop the primary goal completely and reduce the task to a micro-unit (e.g., *open a blank document*, or *write 1 line*). Once momentum returns, restore normal operations.

---

## Pattern 3: Dead Letter Queue (DLQ) for Distracting Ideas
* **Problem:** High-volume associative brains generate intrusive, non-relevant "brilliant" ideas during deep work.
* **Solution:** Route these thoughts to a **Dead Letter Queue (DLQ)**—an isolated, persistent store for unhandled events.
* **Execution:** Park the idea in the DLQ with zero processing, reassuring the mind that the data is persisted without breaking the current focus thread.
